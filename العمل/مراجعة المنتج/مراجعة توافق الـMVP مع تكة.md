# مراجعة توافق الـMVP مع تكة

**تاريخ المراجعة:** 24 أكتوبر 2026  
**النطاق:** فحص `التطبيق/` مقابل `تكة.md`، و`SPEC.md`، و`الوثائق/تكة — الجزيرة الواحدة (v4).md`، مع معاينة صفحة الترحيب والجزيرة.

## الحكم

الـMVP مناسب **كأول نموذج لتجربة تكة**، لكنه ليس تنفيذ الجزيرة الكاملة في v4 ولا تطبيقاً إنتاجياً. الأساس المميز موجود: جزيرة واحدة، خطوة تعلم اختيارية، أثر بناء واضح، فطين، ومكافأة محددة. التغييرات المنفذة هنا تقرّبه من دستور المنتج: أُغلق مسار الحسابات السحابية افتراضياً، وأصبح الخروج من النشاط فورياً مع حفظ موضعه.

## ما يطابق رؤية تكة

| المبدأ | ما يظهر في النسخة | النتيجة |
|---|---|---|
| جزيرة واحدة يبنيها الطفل | خريطة جزيرة واحدة، ثلاثة بيوت تجريبية، مستويات بناء وزينة يحدد الطفل مكانها | مطابق للنسخة التجريبية |
| خطوة تعليم قصيرة واختيارية | بطاقة «تكة اليوم» مع إمكان اختيار مبنى أو فتح المهمات | مطابق؛ لا يوجد قفل عام للتقدم |
| تعلم يقود إلى أثر مرئي | النشاط يمنح نجومًا وألواحًا وعنصراً يوضع على الجزيرة | مطابق على مستوى العينة |
| مكافأة معلومة | الصندوق يشرح شرط إكمال المحطات الثلاث ومحتواه مسبقاً | مطابق؛ لا يوجد سحب عشوائي أو شراء |
| فطين يساعد عند الحاجة | يظهر على الجزيرة ويقدم تلميحاً اختيارياً داخل النشاط | مطابق في الدور؛ رسمه الحالي علامة/رسم مبسط وليس ورقة شخصية نهائية |
| توقف صحي | الخروج الآن يرجع فوراً ويحفظ مسودة النشاط محلياً؛ لا سلاسل عقابية أو مؤقتات أو فقد تقدم | عولجت نقطة عدم التوافق |
| خصوصية وعمل محلي | الضيف لا يحتاج ملفاً سحابياً؛ واجهات الحسابات والـProxy السحابي متوقفة افتراضياً | مطابق لحدود MVP في `تكة.md` |
| الهوية البصرية | RTL وخط Tajawal ولوحة الورق الدافئ والأخضر والحبر البحري والمشمشي، مع رسم هادئ | قريب جداً من الاتجاه؛ الاعتماد النهائي ما زال مطلوباً |

## ما لم يُنفذ بعد

- محتوى التطبيق ثلاثة أنشطة عينة فقط (حرف ب، عدّ حتى أربعة، وتسلسل حكاية). النص يوضح أنها أمثلة، وليست حزمة منهج موثقة أو تغطية صف.
- خريطة الجزيرة الحالية تعرض ثلاثة بيوت. وثيقة v4 تصف تسعة مبانٍ، برج تكة، فتح المساحات، واقتصاداً أوسع. هذه عناصر توسع، ولا يصح وصفها بأنها مكتملة في الـMVP الحالي.
- الاقتصاد الآن نجوم وألواح فقط؛ الحجر والبلورة ومكافآت المراجعة وتدرج الرفاق غير مبنية بالكامل.
- فطين موجود في الواجهة كتجسيد مبسط، لكن ورقة شخصيته ورسومه النهائية وحركاته تحتاج مراجعة واعتماداً.
- النظام البصري الكامل وخريطة الصف الأول ما زالا بحاجة اعتماد؛ لذلك إبقاء الأنشطة محايدة قرار صحيح حتى الآن.

## التعديلات التي أُنجزت

1. تشغيل MVP محلي أولاً: الحسابات والمزامنة غير ظاهرة ولا تستدعي Supabase افتراضياً، والتكامل الموجود محفوظ للمرحلة اللاحقة خلف `NEXT_PUBLIC_TAKKA_CLOUD_ACCOUNTS_ENABLED`.
2. خروج مباشر من النشاط؛ المسودة تحفظ على الجهاز ويستأنف النشاط من موضعه عند فتحه مرة أخرى.
3. تنظيم تقارير البوتات والصور، وأرشفة النسخة المتطابقة من تقرير الرياضيات مع الإبقاء عليها.
4. تحديث الفهارس وملفات README لتصف التطبيق الحالي وحدود محتواه بدلاً من حالة تخطيط قديمة.

## التوصية

احتفظ بهذا البناء كأساس مراجعة للجزيرة وحلقة التعلم، ولا توسّعه بمحتوى صفّي حقيقي قبل اعتماد خريطة الصف الأول. المرحلة التالية ذات القيمة الأعلى: اعتماد الشكل النهائي لفطين والواجهة، ثم تقرير ما إذا كان نطاق الإصدار الأول سيبقى ثلاث محطات أم يتجه إلى المباني التسعة في v4. يبقى Supabase مؤجلاً حتى يعود المالك لهذا المسار.

## التحقق بعد التعديلات

- `npm run typecheck` — ناجح.
- `npm run lint` — ناجح.
- `npm run build` — ناجح على Next.js 16.4.3.
- `npm run test:e2e` — أربعة اختبارات ناجحة؛ اختبار دخول ولي الأمر تخطّى نفسه لأنه يتطلب حساباً تجريبياً وتفعيل الحسابات السحابية.
- معاينة Playwright لصفحة الترحيب والجزيرة على سطح المكتب — ناجحة قبل تعديل الخروج المحلي؛ واختبارات الهاتف، الحفظ دون اتصال واستئناف المحطة ناجحة بعد التعديل.
